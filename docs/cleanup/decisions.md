# Cleanup decisions

Public API and semver decisions made during the cleanup. Each entry: what,
why, the alternative considered, and whether it breaks the 4.x API (a break
needs Vamsi's sign-off before it lands).

| # | Decision | Breaks 4.x? | Status |
|---|---|---|---|
| D1 | **GoAway handling at the wire layer.** `session_loop.rs` returns `DisconnectReason::GoAway` the moment a `goAway` frame arrives, and the connection reconnects with the latest resumption handle. Anything the server still sends on the old connection during `timeLeft` (the end of the model's current sentence, a final transcript) is lost; `session_lifecycle::go_away_reaches_the_callback_and_the_event_stream_with_its_deadline` pins this. Alternative: keep reading the old connection until the server closes it or `timeLeft` elapses, then reconnect. Google's documentation describes `timeLeft` as the time before the server terminates the connection, which argues for draining. Not changed in the cleanup: it is protocol behaviour, and the choice needs Vamsi. | No (behavioural) | Open |
| D2 | **One vocabulary for the SDK, the CLI and Flow Studio.** The SDK's words win, because the document and its JSON keys are the contract the other two surfaces read. Renames to make: Studio "New agent" / "Open JSON…" → "New session spec" / "Open session spec…"; Studio tab "Versions" and button "Save a version" → "Bundles" / "Push a bundle" (the CLI's `bundle push`, the SDK's `bundle` store); Studio panel "Digression" → "Overlay" (the SDK's `overlays`, already "overlay" on the canvas badge); Studio inspector labels "Extraction" / "Watchers" / "MCP servers" → "Extract" / "Watch" / "MCP" (the document keys); Studio "Problems" → "Validation" and "Step through" → "Simulate" (the SDK's `validate` / `simulate`, the CLI's `flow validate` / `flow simulate`); Studio canvas chip "confirm before" → "confirm" (the document's `confirm_tools`); CLI `deploy --region` → `--location` with `--region` kept as a hidden alias one release (the SDK's `location`, `GOOGLE_CLOUD_LOCATION`). Not renamed: `steps` (Flow) and `stages` (ConversationSpec) are two different things and keep their names; CLI `spec`/`flow` command groups stay, since `flow` is the ConversationSpec-only tooling and the inventory's finding is documentation, not a rename. CLI positional `agent_dir` (an `agent.toml` manifest) is a different artefact from a session spec and keeps its name. | No for the SDK; the CLI alias keeps `--region` working | Proposed |
| D3 | **Error types.** Keep one `thiserror` enum per crate as the crate's public error and convert the hand-written ones: fluent's seven `Display + impl Error` types (Conversation, Store, Patch, Answer, Twilio, Srtp, Sip) become `thiserror` enums with the same variants and messages; `FlowError` (adk-rs) and `YamlError` (memory) likewise; server's `StreamTokenError` gains `Display`/`Error`. Add `From` conversions into `AgentError` at the fluent layer for every fluent error and for the genai, flow, workflow, MCP, artifact and memory errors, as new `AgentError` variants with `#[from]` where the error type is public (`Flow(FlowError)`, `Conversation(ConversationError)`, `Store(StoreError)`, `Transport(gemini_genai_rs::...)`, `Memory(MemoryError)`) instead of stringifying into `Config(String)`/`Other(String)`. `Result<_, String>` and `Box<dyn Error>` in public library fns are replaced by the crate error. Adding enum variants to `AgentError` is a breaking change for exhaustive matches unless the enum is `#[non_exhaustive]`; it is not today, so this needs sign-off (the alternative, keeping stringified variants, keeps the 4.x shape and loses the typed information). | Yes: new `AgentError` variants (unless `#[non_exhaustive]` is added, itself a break for exhaustive matchers) | Proposed, awaiting Vamsi |
| D4 | **`HttpClient::new` panics when `reqwest` cannot build a client.** `crates/gemini-genai-rs/src/client/http.rs` `HttpClient::new(config: HttpConfig) -> Self` ends in `reqwest::Client::builder()...build().expect(..)`. `build()` fails when the TLS backend cannot initialise (no usable root store, a broken system TLS config) or when `config.user_agent` is not a valid header value, so this is a real, input- and environment-dependent failure. Callers that cannot return an error today: the `Client::from_api_key`, `from_access_token`, `from_vertex` and `from_vertex_refreshable` constructors and `Client::http_config` (`client/mod.rs`). Proposed: `HttpClient::try_new(config: HttpConfig) -> Result<Self, HttpError>` (reusing `HttpError::Request`), `Client::http_config(self, config) -> Result<Self, HttpError>`, and the four constructors returning `Result<Self, HttpError>` (or a `ClientBuilder::build()` that does). Alternative that keeps every signature: store the build error and return it as `HttpError::Request` from the first request, which moves the failure from construction to first use. Left unchanged in the cleanup because both options change a public signature or defer the error. | Yes | Proposed |
| D5 | **`SessionConfig::to_setup_json` panics if serialization fails.** `crates/gemini-genai-rs/src/protocol/messages/client.rs` `to_setup_json(&self) -> String` calls `serde_json::to_string(&self.to_setup_message()).expect(..)`. The setup message is derived `Serialize` over strings, numbers, enums and `serde_json::Value`, with no custom fallible serializer on that path, so the failure is theoretical, but `serde_json` offers no infallible entry point to prove it. The library has no non-test caller (callers: `tests/golden_wire.rs`, unit tests). Proposed: `to_setup_json(&self) -> Result<String, serde_json::Error>`; additive alternative: keep `to_setup_json` and add `try_to_setup_json`, deprecating the panicking one. | Yes | Proposed |
| D6 | **`Recognizer::regex` and `SlotRecognizer::to_recognizer` panic on an invalid pattern.** `crates/gemini-adk-rs/src/extract/mod.rs` `Recognizer::regex(pattern: &str) -> Self` does `Regex::new(pattern).expect("invalid recognizer regex")`. The pattern is caller data: the `#[recognize(regex = "..")]` derive passes a literal, but `SlotRecognizer::Regex(String)` (`frame.rs`) is `Serialize`/`Deserialize` and is lowered by `SlotRecognizer::to_recognizer(&self) -> Recognizer`, so a spec loaded from JSON/YAML (Flow Studio, `ConversationSpec`) can carry a bad pattern and abort the process. Proposed: `Recognizer::try_regex(pattern: &str) -> Result<Self, regex::Error>` (or `ExtractError::InvalidPattern`), `SlotRecognizer::to_recognizer(&self) -> Result<Recognizer, regex::Error>`, and the `Extract` derive validating the literal at expansion time. Keep `Recognizer::regex` only as a documented panicking convenience for literals, or remove it. | Yes | Proposed |
| D7 | **`wire_schema` and `conversation_spec_schema` serialize a `schemars` schema with a panicking call.** `crates/gemini-adk-rs/src/tool/schema.rs` `wire_schema<T>() -> serde_json::Value` does `serde_json::to_value(root).expect(..)`, and `crates/gemini-adk-fluent-rs/src/conversation.rs` `conversation_spec_schema() -> String` does `serde_json::to_string_pretty(&schema).expect(..)`. A `schemars` 0.8 `RootSchema` is plain data with string keys, so neither can fail, but 0.8 has no conversion to `Value` that is not `Result`-typed. `wire_schema` is called from `TypedTool`, `text/mod.rs`, the fluent `output_schema`/extraction builders and macro-generated code, none of which can return an error. Proposed: move to `schemars` 1.x, where `Schema` wraps a `serde_json::Value` and the conversion is infallible (no signature change), or add `try_wire_schema::<T>() -> Result<Value, serde_json::Error>` and `try_conversation_spec_schema()` and keep the current functions as panicking wrappers. | Yes | Proposed |
| D8 | **`SessionSpec::to_rust` panics if the spec does not serialize.** `crates/gemini-adk-fluent-rs/src/spec/codegen.rs` `to_rust(&self) -> String` does `serde_json::to_string_pretty(self).expect("session specs serialize")` for specs that carry skills or a conversation. `SessionSpec` is derived `Serialize` and holds `serde_json::Value` fields and `BTreeMap<String, _>` maps, so the call cannot fail today, but it stays infallible only while every nested type keeps string keys and no fallible custom serializer is added; the type system does not guarantee that. Callers: Flow Studio (`apps/gemini-adk-web-rs/src/studio.rs`) and the round-trip tests. Proposed: `to_rust(&self) -> Result<String, serde_json::Error>` (or a `CodegenError`). The two other `expect(` hits in that file are string literals inside the generated program text, not calls in the library. | Yes | Proposed |
| D9 | **The `DspStage::process` implementations unwrap FFT and resampler results.** `voice/dsp/aec.rs` (5 sites: far-end, error and constraint forward FFTs, echo and constraint inverse FFTs), `voice/dsp/stft.rs` (forward and inverse FFT) and `voice/dsp/resample.rs` (`SequentialSliceOfVecs::new`, `new_mut` and `process_into_buffer`) call `realfft` and `rubato` APIs that return `Result`. The buffer-size errors cannot occur because every buffer is sized at construction, but `realfft`'s complex-to-real transform returns `FftError::InputValues` when the DC or Nyquist imaginary part is non-zero, and a NaN or infinite sample reaching the AEC filter state, or a user `SpectralStage` that writes those bins, makes that real: today it aborts the audio task. `DspStage::process(&mut self, bus: &mut AudioBus)` and `InputAudioProcessor::process_frame` return `()`, so there is no channel for the error. Proposed: `DspStage::process(&mut self, bus) -> Result<(), DspError>` with `DspChain` choosing the policy (bypass the faulted stage and count it in `ChainMetrics`, or surface the error to the session). Alternative without an API change: each stage latches a fault flag on error, becomes a pass-through and logs once; that is a behavioural choice and needs sign-off. | Yes | Proposed |
| D10 | **`SincResampler::new` panics on rates `rubato` rejects.** `crates/gemini-adk-fluent-rs/src/voice/dsp/resample.rs` `SincResampler::new(from_hz: u32, to_hz: u32) -> Self` does `Async::<f32>::new_sinc(..).expect("valid resampler parameters")`; a zero rate or an extreme ratio is rejected by `rubato` (`ResamplerConstructionError`). Proposed: `SincResampler::try_new(from_hz, to_hz) -> Result<Self, rubato::ResamplerConstructionError>` and `new` kept only if documented as panicking on invalid rates. | Yes | Proposed |
| D11 | **Two eval-set configs named `TestConfig`.** `gemini_adk_rs::evaluation::TestConfig` (`evaluation/test_config.rs`) is `{ criteria: HashMap<String, CriterionConfig> }`, where a criterion is a bare threshold number or `{ threshold, judge_model, num_samples }`, loaded from `test_config.json`. The CLI's private `TestConfig` (`tools/gemini-adk-cli-rs/src/commands/eval.rs`) is `{ pass_threshold (default 0.7), criteria: Vec<Criterion> }` read by `adk eval --config-file`. The CLI does not use the SDK type, and a file written for one is rejected by the other. Proposed single type: the SDK's `TestConfig`, extended with an optional `pass_threshold` (the CLI's default 0.7 becomes the SDK default for a criterion given no threshold) and a `Criterion` list form accepted next to the map form through a `#[serde(untagged)]` wrapper, so both existing file shapes load; the CLI then drops its copy and calls `TestConfig::from_file`. Not merged here because both are public file formats and the CLI's list form has no SDK equivalent. Alternative: rename the CLI type `CliEvalConfig` and document two formats (no migration, two schemas stay). Break scope: no for the SDK if the map form keeps loading; the CLI's file format keeps working too. | Yes | Proposed |
| D12 | **Three `EvalCase` types for three jobs.** `gemini_adk_rs::evaluation::EvalCase` (`eval_case.rs`) is `{ name, actual: Vec<Invocation>, expected: Vec<Invocation>, scenario }`, a recorded conversation with golden turns, and sits in `EvalSet`. `gemini_adk_fluent_rs::compose::eval::EvalCase` is `{ prompt, expected }`, a single-turn string pair for `EvalSuite`. The CLI's private `EvalCase` (`commands/eval.rs`) is `{ id, inputs: Vec<String>, expected: Vec<String>, tags }` read from an eval-set file. Same concept (an input and what it should produce), three schemas, and the fluent and SDK ones share a name in the same prelude path. Proposed single type: the SDK `EvalCase`, with `From<(prompt, expected)>` for the single-turn builder and a loader that turns the CLI's `inputs`/`expected` string lists into `Invocation`s; `tags` becomes `metadata`. The fluent one then becomes a builder that produces SDK cases, not a type of its own. Not merged here: public types with different serde shapes. Break scope: yes if the fluent `EvalCase` is removed or re-typed; No if it is kept as a builder alias. | Yes | Proposed |
| D13 | **`CodeExecutionResult` in the wire layer and in the code-executor layer.** `gemini_genai_rs::protocol::types::CodeExecutionResult` (`content.rs`) is the Live/generateContent wire part `{ outcome: String, output: Option<String> }` (camelCase). `gemini_adk_rs::code_executors::CodeExecutionResult` (`types.rs`) is a local sandbox's result `{ stdout, stderr, output_files }`. They are different stages of one story (the model asks for code to run, a runner runs it, the answer goes back as the wire part) but share a name, and no `From` conversion links them (`code_executors/utils.rs` builds the wire part by hand). Proposed: keep both shapes (the wire type must match the API), rename the adk-rs one `ExecutionOutput` with `#[deprecated] pub type CodeExecutionResult = ExecutionOutput` for one release, and add `impl From<ExecutionOutput> for gemini_genai_rs::...::CodeExecutionResult` (`outcome` from the exit status, `output` from `stdout`, `stderr` appended on failure). Resolves the name collision without merging unlike shapes. Break scope: no with the deprecated alias; Yes if the alias is dropped. | Yes | Proposed |
| D14 | **Three agent-definition-file types.** `gemini_adk_rs::AgentConfig` (`agent_config.rs`) is the rich schema: optional `model`, nested `sub_agents: Vec<AgentConfig>`, `tools: Vec<ToolConfig>`, sampling, `output_schema`, `agent_type`, voice and greeting, `a2a`, `env`. The server's `AgentEntry` plus private `TomlManifest` (`agents.rs`) is a flat subset (`tools` and `sub_agents` as name lists; `model` defaults to `gemini-2.0-flash`) that the server converts from `AgentConfig` in one place and from `agent.toml` in another. The CLI's `AgentManifest` (`manifest.rs`) is another flat subset reading the same `agent.toml` but adding `temperature`, `thinking`, `greeting`, `voice`, `output_modality` and defaulting `model` to `gemini-flash-latest`. So one `agent.toml` loads into two types that disagree on defaults and on which keys they know. Proposed single type: `AgentConfig` as the file schema (it already has every key either subset names, except `output_modality` and the name-list forms of `tools` / `sub_agents`, which become `#[serde(untagged)]` accepted forms); `AgentEntry` stays as the server's API view built with `From<&AgentConfig>`; both `TomlManifest` and `AgentManifest` are deleted; the default model comes from `GeminiLlm`'s per-variant default (one value) instead of two literals. The default-model change is behaviour: a server agent without `model` moves from `gemini-2.0-flash` to the SDK default. Break scope: yes for the default model of server agents without a `model`; the types themselves are private or additive. | Yes | Proposed |
| D15 | **`AgentEvent` as an enum and as a serialized struct.** `gemini_adk_rs::AgentEvent` (`context.rs`) is the typed event enum (`Session`, `AgentStarted`, `ToolCallStarted` / `Completed` / `Failed`, ...). The server's `AgentEvent` (`types.rs`) is `{ event_type: String, data: Value }`, the JSON view of the same events that `ChannelEvents` builds by hand per variant. The string `event_type` names and `data` shapes live only in that conversion, so a new SDK variant is silently dropped or mis-named on the wire. Proposed single type: give the SDK enum a `Serialize` impl (or `AgentEvent::to_wire() -> WireEvent { event_type, data }` in adk-rs, next to the enum) and have the server's struct become a re-export of that wire type, so the mapping is written once and exhaustive. Not done here: the server type is public API with a fixed JSON shape, and the mapping has to keep `event_type` strings byte-identical. Break scope: no if the wire strings and shapes are preserved; Yes if they are normalised. | Yes | Proposed |
| D16 | **The next release is a major.** `cargo semver-checks` against the published 4.0.0 (run 2026-11-06, `scratchpad/logs/semver.log`) reports breaks that pre-date the cleanup: new public fields on `SessionSpec` (`models`, `decisions`, `code`), `ExtractSpec` (`model`, `thinking_budget`), `ToolSpec` (`returns`), `SkillSpec` (`code`), `SpecResources` (`models`, `decision_model`, `code_sandbox`), `CompiledSkill` (`code`), `GeminiLlmParams` (`base_url`); new variants on the exhaustive enums `SimStep::Decide`, `SteeringSpec::ContextUpdate`, `SteeringMode::ContextUpdate`, `Pred::Decided`, `SessionCommand::UpdateContext`. The cleanup adds `HttpError::InvalidMethod`, `CachesError::Serialize`, `EmbedError::Serialize` (D2) and only additive items otherwise (`FramePayload`, the `utils::text`/`utils::time` helpers, the env helpers including `non_empty_env`, `MockLlm::echo`, `agent_config::default_agent_type` and `spec::resolve_voice` made `pub`, the server crate's `telemetry` and `web_handlers` modules and `execution::{extraction_llm_params, build_extraction_llm}` (shared with the web app); and `FlowBuilder` misuse (`after`/`when` on an unknown step) now surfaces as a `build()` error instead of a panic, which is a behaviour change in the lenient direction). Options: (a) release 5.0.0 and, in the same release, mark every public error enum and the spec/config structs `#[non_exhaustive]` so later additions stop being breaks; (b) revert the three error variants into existing ones and keep 4.x, which does not help since the pre-existing breaks remain. Recommendation: (a). The `release.yml` semver step will fail on the current main until the version is bumped. | Yes (already true on main) | Proposed, awaiting Vamsi |
| D17 | **The Python binding is a new public surface, shaped as Vamsi asked: one PyO3 cdylib built by maturin, `import gemini_adk`, nothing else to build.** Surface: `Agent`/`Chat`/`EventStream`, `Tool` and the `@tool` decorator (sync on the blocking pool, async on the creating asyncio loop), `MockLlm`, `LiveSession`/`LiveEvents` with `connect()` and `scripted()`, `SessionSpec`, `Conversation`/`Sim`, `conversation_schema()`/`validate_conversation()`, one exception hierarchy under `GeminiAdkError`. The earlier handle-based JSON data plane (`spec_schema`, `compile_spec`, `sim_new`, ... with integer handles) is removed; the crate was never published, so nothing breaks. Rust side unchanged except test-only hooks on the module (`_raise`, `_variants`, `_thread_token`, `_inside_runtime`, `_probe`). Left for Vamsi: the PyPI distribution name and import name (today `gemini-adk` / `gemini_adk`); nothing is published until confirmed. Backpressure policy, lane rules and cancellation are in `python-binding-design.md` §1–§4 (§10 lists what shipped and what is deferred) and are held by the pytest suite (`fast_lane_never_sees_python`, `slow_consumer_does_not_stall_fast_lane`, `lagged_event_counts_every_drop_in_order`, `async_tool_is_cancelled_on_barge_in`, `block_on_inside_worker_is_an_error`, `fork_after_init_is_refused`, `every_variant_maps`, `typed_answer_retries_once`). | No (new crate, never published) | Done, name awaiting Vamsi |
| D18 | **API-key precedence.** The deduplication (D3) gave every surface one rule, `api_key_from_env`: `GEMINI_API_KEY`, then `GOOGLE_GENAI_API_KEY`, then `GOOGLE_API_KEY`, empty values ignored. The Live/session path already used that order; `GeminiLlm::from_env` tried `GOOGLE_GENAI_API_KEY` first and accepted an empty string. A process exporting two different keys now picks the other one on the text path. The same unification makes `vertex_requested` accept `"1"` as well as `"true"` everywhere (the web app required `"true"`), and `adk doctor` no longer reads the undocumented `GOOGLE_PROJECT_ID` fallback (`GOOGLE_CLOUD_PROJECT` is the documented variable). Options: keep the unified order (documented in the CHANGELOG; matches the Live path and Google's own `GEMINI_API_KEY` naming), or restore the old order for `GeminiLlm` alone and keep two rules. Recommendation: keep one rule. | Behavioural, on a 4.x constructor | Done; Vamsi may reverse |
| D19 | **Timestamps on the wire are RFC 3339.** The server's `SessionData.created_at`/`updated_at`, trace `started_at` and eval `timestamp`, and the runtime's `Session::created_at`/`updated_at`, were `"{unix_seconds}Z"` (for example `1730000000Z`), which no RFC 3339 parser accepts; they are now `2024-02-29T12:34:56Z` through one helper (`utils::time::now_rfc3339`), the form the Vertex session store already wrote. No signature changes; a client that parsed the old value as an integer sees a different string. Alternative: keep the old value and add a second field, which keeps a wrong format alive. | Behavioural (JSON values) | Done; Vamsi may reverse |
