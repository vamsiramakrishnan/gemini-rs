# Cleanup decisions

Public API and semver decisions made during the cleanup. Each entry: what,
why, the alternative considered, and whether it breaks the 4.x API (a break
needs Vamsi's sign-off before it lands).

| # | Decision | Breaks 4.x? | Status |
|---|---|---|---|
| D1 | **GoAway handling at the wire layer.** `session_loop.rs` returns `DisconnectReason::GoAway` the moment a `goAway` frame arrives, and the connection reconnects with the latest resumption handle. Anything the server still sends on the old connection during `timeLeft` (the end of the model's current sentence, a final transcript) is lost; `session_lifecycle::go_away_reaches_the_callback_and_the_event_stream_with_its_deadline` pins this. Alternative: keep reading the old connection until the server closes it or `timeLeft` elapses, then reconnect. Google's documentation describes `timeLeft` as the time before the server terminates the connection, which argues for draining. Not changed in the cleanup: it is protocol behaviour, and the choice needs Vamsi. | No (behavioural) | Open |
| D2 | **One vocabulary for the SDK, the CLI and Flow Studio.** The SDK's words win, because the document and its JSON keys are the contract the other two surfaces read. Renames to make: Studio "New agent" / "Open JSON…" → "New session spec" / "Open session spec…"; Studio tab "Versions" and button "Save a version" → "Bundles" / "Push a bundle" (the CLI's `bundle push`, the SDK's `bundle` store); Studio panel "Digression" → "Overlay" (the SDK's `overlays`, already "overlay" on the canvas badge); Studio inspector labels "Extraction" / "Watchers" / "MCP servers" → "Extract" / "Watch" / "MCP" (the document keys); Studio "Problems" → "Validation" and "Step through" → "Simulate" (the SDK's `validate` / `simulate`, the CLI's `flow validate` / `flow simulate`); Studio canvas chip "confirm before" → "confirm" (the document's `confirm_tools`); CLI `deploy --region` → `--location` with `--region` kept as a hidden alias one release (the SDK's `location`, `GOOGLE_CLOUD_LOCATION`). Not renamed: `steps` (Flow) and `stages` (ConversationSpec) are two different things and keep their names; CLI `spec`/`flow` command groups stay, since `flow` is the ConversationSpec-only tooling and the inventory's finding is documentation, not a rename. CLI positional `agent_dir` (an `agent.toml` manifest) is a different artefact from a session spec and keeps its name. | No for the SDK; the CLI alias keeps `--region` working | Proposed |
| D3 | **Error types.** Keep one `thiserror` enum per crate as the crate's public error and convert the hand-written ones: fluent's seven `Display + impl Error` types (Conversation, Store, Patch, Answer, Twilio, Srtp, Sip) become `thiserror` enums with the same variants and messages; `FlowError` (adk-rs) and `YamlError` (memory) likewise; server's `StreamTokenError` gains `Display`/`Error`. Add `From` conversions into `AgentError` at the fluent layer for every fluent error and for the genai, flow, workflow, MCP, artifact and memory errors, as new `AgentError` variants with `#[from]` where the error type is public (`Flow(FlowError)`, `Conversation(ConversationError)`, `Store(StoreError)`, `Transport(gemini_genai_rs::...)`, `Memory(MemoryError)`) instead of stringifying into `Config(String)`/`Other(String)`. `Result<_, String>` and `Box<dyn Error>` in public library fns are replaced by the crate error. Adding enum variants to `AgentError` is a breaking change for exhaustive matches unless the enum is `#[non_exhaustive]`; it is not today, so this needs sign-off (the alternative, keeping stringified variants, keeps the 4.x shape and loses the typed information). | Yes: new `AgentError` variants (unless `#[non_exhaustive]` is added, itself a break for exhaustive matchers) | Proposed, awaiting Vamsi |
| D4 | **`HttpClient::new` panics when `reqwest` cannot build a client.** `crates/gemini-genai-rs/src/client/http.rs` `HttpClient::new(config: HttpConfig) -> Self` ends in `reqwest::Client::builder()...build().expect(..)`. `build()` fails when the TLS backend cannot initialise (no usable root store, a broken system TLS config) or when `config.user_agent` is not a valid header value, so this is a real, input- and environment-dependent failure. Callers that cannot return an error today: the `Client::from_api_key`, `from_access_token`, `from_vertex` and `from_vertex_refreshable` constructors and `Client::http_config` (`client/mod.rs`). Proposed: `HttpClient::try_new(config: HttpConfig) -> Result<Self, HttpError>` (reusing `HttpError::Request`), `Client::http_config(self, config) -> Result<Self, HttpError>`, and the four constructors returning `Result<Self, HttpError>` (or a `ClientBuilder::build()` that does). Alternative that keeps every signature: store the build error and return it as `HttpError::Request` from the first request, which moves the failure from construction to first use. Left unchanged in the cleanup because both options change a public signature or defer the error. | Yes | Proposed |
| D5 | **`SessionConfig::to_setup_json` panics if serialization fails.** `crates/gemini-genai-rs/src/protocol/messages/client.rs` `to_setup_json(&self) -> String` calls `serde_json::to_string(&self.to_setup_message()).expect(..)`. The setup message is derived `Serialize` over strings, numbers, enums and `serde_json::Value`, with no custom fallible serializer on that path, so the failure is theoretical, but `serde_json` offers no infallible entry point to prove it. The library has no non-test caller (callers: `tests/golden_wire.rs`, unit tests). Proposed: `to_setup_json(&self) -> Result<String, serde_json::Error>`; additive alternative: keep `to_setup_json` and add `try_to_setup_json`, deprecating the panicking one. | Yes | Proposed |
| D6 | **`Recognizer::regex` and `SlotRecognizer::to_recognizer` panic on an invalid pattern.** `crates/gemini-adk-rs/src/extract/mod.rs` `Recognizer::regex(pattern: &str) -> Self` does `Regex::new(pattern).expect("invalid recognizer regex")`. The pattern is caller data: the `#[recognize(regex = "..")]` derive passes a literal, but `SlotRecognizer::Regex(String)` (`frame.rs`) is `Serialize`/`Deserialize` and is lowered by `SlotRecognizer::to_recognizer(&self) -> Recognizer`, so a spec loaded from JSON/YAML (Flow Studio, `ConversationSpec`) can carry a bad pattern and abort the process. Proposed: `Recognizer::try_regex(pattern: &str) -> Result<Self, regex::Error>` (or `ExtractError::InvalidPattern`), `SlotRecognizer::to_recognizer(&self) -> Result<Recognizer, regex::Error>`, and the `Extract` derive validating the literal at expansion time. Keep `Recognizer::regex` only as a documented panicking convenience for literals, or remove it. | Yes | Proposed |
| D7 | **`wire_schema` and `conversation_spec_schema` serialize a `schemars` schema with a panicking call.** `crates/gemini-adk-rs/src/tool/schema.rs` `wire_schema<T>() -> serde_json::Value` does `serde_json::to_value(root).expect(..)`, and `crates/gemini-adk-fluent-rs/src/conversation.rs` `conversation_spec_schema() -> String` does `serde_json::to_string_pretty(&schema).expect(..)`. A `schemars` 0.8 `RootSchema` is plain data with string keys, so neither can fail, but 0.8 has no conversion to `Value` that is not `Result`-typed. `wire_schema` is called from `TypedTool`, `text/mod.rs`, the fluent `output_schema`/extraction builders and macro-generated code, none of which can return an error. Proposed: move to `schemars` 1.x, where `Schema` wraps a `serde_json::Value` and the conversion is infallible (no signature change), or add `try_wire_schema::<T>() -> Result<Value, serde_json::Error>` and `try_conversation_spec_schema()` and keep the current functions as panicking wrappers. | Yes | Proposed |
| D8 | **`SessionSpec::to_rust` panics if the spec does not serialize.** `crates/gemini-adk-fluent-rs/src/spec/codegen.rs` `to_rust(&self) -> String` does `serde_json::to_string_pretty(self).expect("session specs serialize")` for specs that carry skills or a conversation. `SessionSpec` is derived `Serialize` and holds `serde_json::Value` fields and `BTreeMap<String, _>` maps, so the call cannot fail today, but it stays infallible only while every nested type keeps string keys and no fallible custom serializer is added; the type system does not guarantee that. Callers: Flow Studio (`apps/gemini-adk-web-rs/src/studio.rs`) and the round-trip tests. Proposed: `to_rust(&self) -> Result<String, serde_json::Error>` (or a `CodegenError`). The two other `expect(` hits in that file are string literals inside the generated program text, not calls in the library. | Yes | Proposed |
| D9 | **The `DspStage::process` implementations unwrap FFT and resampler results.** `voice/dsp/aec.rs` (5 sites: far-end, error and constraint forward FFTs, echo and constraint inverse FFTs), `voice/dsp/stft.rs` (forward and inverse FFT) and `voice/dsp/resample.rs` (`SequentialSliceOfVecs::new`, `new_mut` and `process_into_buffer`) call `realfft` and `rubato` APIs that return `Result`. The buffer-size errors cannot occur because every buffer is sized at construction, but `realfft`'s complex-to-real transform returns `FftError::InputValues` when the DC or Nyquist imaginary part is non-zero, and a NaN or infinite sample reaching the AEC filter state, or a user `SpectralStage` that writes those bins, makes that real: today it aborts the audio task. `DspStage::process(&mut self, bus: &mut AudioBus)` and `InputAudioProcessor::process_frame` return `()`, so there is no channel for the error. Proposed: `DspStage::process(&mut self, bus) -> Result<(), DspError>` with `DspChain` choosing the policy (bypass the faulted stage and count it in `ChainMetrics`, or surface the error to the session). Alternative without an API change: each stage latches a fault flag on error, becomes a pass-through and logs once; that is a behavioural choice and needs sign-off. | Yes | Proposed |
| D10 | **`SincResampler::new` panics on rates `rubato` rejects.** `crates/gemini-adk-fluent-rs/src/voice/dsp/resample.rs` `SincResampler::new(from_hz: u32, to_hz: u32) -> Self` does `Async::<f32>::new_sinc(..).expect("valid resampler parameters")`; a zero rate or an extreme ratio is rejected by `rubato` (`ResamplerConstructionError`). Proposed: `SincResampler::try_new(from_hz, to_hz) -> Result<Self, rubato::ResamplerConstructionError>` and `new` kept only if documented as panicking on invalid rates. | Yes | Proposed |
