# Cleanup decisions

Public API and semver decisions made during the cleanup. Each entry: what,
why, the alternative considered, and whether it breaks the 4.x API (a break
needs Vamsi's sign-off before it lands).

| # | Decision | Breaks 4.x? | Status |
|---|---|---|---|
| D1 | **GoAway handling at the wire layer.** `session_loop.rs` returns `DisconnectReason::GoAway` the moment a `goAway` frame arrives, and the connection reconnects with the latest resumption handle. Anything the server still sends on the old connection during `timeLeft` (the end of the model's current sentence, a final transcript) is lost; `session_lifecycle::go_away_reaches_the_callback_and_the_event_stream_with_its_deadline` pins this. Alternative: keep reading the old connection until the server closes it or `timeLeft` elapses, then reconnect. Google's documentation describes `timeLeft` as the time before the server terminates the connection, which argues for draining. Not changed in the cleanup: it is protocol behaviour, and the choice needs Vamsi. | No (behavioural) | Open |
| D2 | **One vocabulary for the SDK, the CLI and Flow Studio.** The SDK's words win, because the document and its JSON keys are the contract the other two surfaces read. Renames to make: Studio "New agent" / "Open JSON…" → "New session spec" / "Open session spec…"; Studio tab "Versions" and button "Save a version" → "Bundles" / "Push a bundle" (the CLI's `bundle push`, the SDK's `bundle` store); Studio panel "Digression" → "Overlay" (the SDK's `overlays`, already "overlay" on the canvas badge); Studio inspector labels "Extraction" / "Watchers" / "MCP servers" → "Extract" / "Watch" / "MCP" (the document keys); Studio "Problems" → "Validation" and "Step through" → "Simulate" (the SDK's `validate` / `simulate`, the CLI's `flow validate` / `flow simulate`); Studio canvas chip "confirm before" → "confirm" (the document's `confirm_tools`); CLI `deploy --region` → `--location` with `--region` kept as a hidden alias one release (the SDK's `location`, `GOOGLE_CLOUD_LOCATION`). Not renamed: `steps` (Flow) and `stages` (ConversationSpec) are two different things and keep their names; CLI `spec`/`flow` command groups stay, since `flow` is the ConversationSpec-only tooling and the inventory's finding is documentation, not a rename. CLI positional `agent_dir` (an `agent.toml` manifest) is a different artefact from a session spec and keeps its name. | No for the SDK; the CLI alias keeps `--region` working | Proposed |
| D3 | **Error types.** Keep one `thiserror` enum per crate as the crate's public error and convert the hand-written ones: fluent's seven `Display + impl Error` types (Conversation, Store, Patch, Answer, Twilio, Srtp, Sip) become `thiserror` enums with the same variants and messages; `FlowError` (adk-rs) and `YamlError` (memory) likewise; server's `StreamTokenError` gains `Display`/`Error`. Add `From` conversions into `AgentError` at the fluent layer for every fluent error and for the genai, flow, workflow, MCP, artifact and memory errors, as new `AgentError` variants with `#[from]` where the error type is public (`Flow(FlowError)`, `Conversation(ConversationError)`, `Store(StoreError)`, `Transport(gemini_genai_rs::...)`, `Memory(MemoryError)`) instead of stringifying into `Config(String)`/`Other(String)`. `Result<_, String>` and `Box<dyn Error>` in public library fns are replaced by the crate error. Adding enum variants to `AgentError` is a breaking change for exhaustive matches unless the enum is `#[non_exhaustive]`; it is not today, so this needs sign-off (the alternative, keeping stringified variants, keeps the 4.x shape and loses the typed information). | Yes: new `AgentError` variants (unless `#[non_exhaustive]` is added, itself a break for exhaustive matchers) | Proposed, awaiting Vamsi |
